# 识别、尺度与家具映射

## 实际执行时的观察清单

先看全图：边界是否完整、几室几厅、入户位置、开放空间与封闭空间。随后分别放大尺寸和门窗、厨房卫浴、家具密集处。明确哪些线是尺寸线、门弧、柜体、窗框，不能一律转成墙。

建议记录像素观测再转换：`x_mm=(x_px-origin_x)*s`，`y_mm=(y_px-origin_y)*s`。校正图像上的已知线段长 `L_mm`、像素长 `L_px`，则 `s=L_mm/L_px`。多条标注有冲突时先查是否是内净距和外包距混淆，再查截图拉伸或透视，不要把所有误差都塞进墙厚。

如果图像被等比缩放，可统一一个 s；如果确实被非等比拉伸，先校正图片，再重新标定。单靠户型建筑面积无法直接推导套内净面积，不要用“建筑面积100平”强行缩放房间面积总和到100平。

## 家具视觉线索与默认先验

目录中的所有可用 type 和默认尺寸见 furniture-catalog.json。根据轮廓和功能映射，不根据 OCR 名字机械匹配。

| 图中物体 | type | 识别与尺寸注意 |
|---|---|---|
| 床与枕头 | bed | 枕头侧是床头；宽常见1200/1500/1800，深约2000，均只是先验 |
| 沙发 | sofa / cornersofa / armchair | L形用cornersofa，但模板贵妃位手性固定；与原图相反时明确说明造型近似 |
| 衣柜、通顶柜 | wardrobe | 用墙边长条范围，柜深常见550～600；高度是模型默认 |
| 餐边/储物柜 | cabinet | 不应仅凭长条轮廓都判成衣柜 |
| 餐桌、圆桌 | table / roundtable | 桌椅分开建实例；不要用一个含椅子的检测框作为桌面尺寸 |
| 茶几、地毯 | coffeetable / rug | 两者允许叠放；地毯不是房间地面边界 |
| 橱柜台面 | counter | L/U形拆成直段；交角避免重复面积，可作为一个组合记录 |
| 灶台、水槽 | stove / ksink | 可叠放在counter上；模板有相应默认模型高度 |
| 卫浴 | toilet / vanity / shower / bathtub | 马桶朝向注意水箱在背部；淋浴图形不等于实墙 |
| 家电 | fridge / washer / dryer / dishwasher / tv | 识别后沿同一图纸尺度估计，无法分清洗烘时记录歧义 |
| 桌椅 | desk / chair / officechair | 观察靠背确定椅子方向；不要把椅背当墙 |

无可靠尺度时，用1～2个清晰的大件作为估计锚点，再核对门宽、通道和其他家具比例。不要用自己估计的床尺寸“验证”同一估计得出的房间尺寸，两者不是独立证据。

旋转转换示例：图中床头在右，床的水平像素长约200、竖直宽约180；若 s=10，则 `w=1800,d=2000,rot=90`。中心由图像有向框中心转换，不是左上角。

## 建筑复核与失败处理

- 墙端点吸附、共线合并应依据图像和明确容差；不能为了强制闭合而大幅改变房间形状。
- 房间轮廓与墙体几何须一致，共墙只一份；门洞和窗洞不与实体墙重叠。
- 像素模糊无法判断的位置，在 uncertainties 里列具体对象及影响，而非只写“可能有误”。
- 看不到的门窗不要补成“已识别”；承重未标注用 u，层高等使用默认值必须披露。
- 生成后把原图与2D矢量叠加。优先修复房间相邻关系和门位置，再修尺寸和家具偏移。
- 可以在同一张图中保留“确认”和“估计”的混合信息，不能因为少量尺寸不确定就用内置示例替代整图。

## 交付措辞

报告实际恢复了多少房间、墙段、门窗和家具，尺度来自哪些标注、哪些尺寸为估计，是否完成浏览器2D/3D验收。若没有真实用户图片，只能称为合成案例流程测试，不能声称已验证小红书图片识别准确率。
